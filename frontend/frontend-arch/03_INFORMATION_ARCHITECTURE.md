# Purpose

This document defines the information architecture of Prometheus Swarm.

It specifies:

- Primary navigation
- Workspace hierarchy
- Core entities
- Relationships between entities
- Navigation model
- Object ownership
- Data organization
- User mental model

The goal is to ensure every feature belongs to a logical location within the platform.

---

# Design Philosophy

Prometheus Swarm is organized around engineering work.

Not conversations.

Not pages.

Not AI models.

Everything revolves around **Projects** and **Missions**.

Users should always understand:

- Where they are
- What they are working on
- What belongs to the current project
- What belongs to the current mission

---

# Core Mental Model

```
Workspace

└── Projects

      └── Missions

            └── Agents

                  └── Artifacts
```

Projects contain missions.

Missions coordinate agents.

Agents generate artifacts.

Artifacts become permanent project assets.

---

# Core Entities

The platform is built around the following primary entities.

---

## Workspace

The highest-level container.

Contains:

- Projects
- Models
- Datasets
- Deployments
- Knowledge Base
- User Settings

---

## Project

Represents one long-term AI solution.

Examples:

- Medical Diagnosis
- Face Recognition
- OCR Platform
- Financial Forecasting

Each project contains:

- Mission history
- Models
- Datasets
- Artifacts
- Deployments
- Documentation

Projects persist indefinitely.

---

## Mission

Represents a single execution of the swarm.

Examples:

- Build initial system
- Improve accuracy
- Add authentication
- Retrain model
- Deploy production version

Every mission has:

- Status
- Timeline
- Workflow
- Logs
- Agent executions
- Generated artifacts

Missions are temporary.

Projects are permanent.

---

## Agent

A specialized autonomous worker.

Examples:

- Scout
- Forge
- Furnace
- Dissect
- Arbiter
- Harbor

Each agent has:

- Role
- State
- Prompt
- Memory
- Tool usage
- Outputs
- Runtime metrics

---

## Artifact

Anything generated by the swarm.

Examples:

- Python files
- Dockerfiles
- Reports
- Models
- Metrics
- Documentation
- Images
- Logs

Artifacts belong to projects.

Never to chat conversations.

---

## Model

Represents a trained AI model.

Stores:

- Version
- Metrics
- Dataset
- Configuration
- Deployment status

---

## Dataset

Represents uploaded or generated data.

Contains:

- Metadata
- Version
- Size
- Source
- Validation
- Usage history

---

## Deployment

Represents a deployed project.

Contains:

- Endpoint
- Environment
- Health
- Monitoring
- Version
- Logs

---

# Notification Hierarchy

Notifications are grouped by severity.

Critical

Deployment failures

Agent crashes

Training failures

Warnings

Validation issues

Performance degradation

Information

Mission started

Mission completed

Artifact generated

Deployment successful

---

# Information Hierarchy

Every page should prioritize information in this order.

1. Current Status
2. Current Mission
3. Current Progress
4. Important Actions
5. Generated Outputs
6. Supporting Details
7. Historical Data

This hierarchy should remain consistent throughout the platform.

---

# Conclusion

Prometheus Swarm organizes information around **Projects**, **Missions**, **Agents**, and **Artifacts** rather than conversations.

This architecture reflects the complete AI engineering lifecycle and provides a scalable foundation for future capabilities while maintaining a consistent and intuitive user experience.
